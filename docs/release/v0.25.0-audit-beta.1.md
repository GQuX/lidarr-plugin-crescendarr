# Crescendarr v0.25.0-audit-beta.1: audit-only pre-release (release notes draft, NOT PUBLISHED)

Minimum Lidarr Version: 3.1.6.5079

> **Audit-only, read-only preview.** This build cannot import, move, delete, retag, relink or recycle anything in your
> library, and it never touches your download clients. It shows what a selective import *would* do.

## What it does

For completed downloads from the Lidarr download clients **you select**, Crescendarr previews per track:
- **Upgrade**: the incoming file is better according to your quality profile.
- **Keep**: your existing file is better.
- **Add**: the track is missing from your library.
- **Review**: the case is ambiguous, for example a wrong edition.

Each row gives the reason, the current and incoming quality, and whether your lyric file would be kept.

Results appear in three places:
- as a yellow warning in System > Status;
- in `<AppData>/crescendarr-audit/report.md` and `report.json`;
- in `diagnostics-redacted.json`, which is safe to share.

It starts **Disabled**. Nothing is observed until you turn on *Audit only* and select clients in Settings > Connect > Crescendarr.

## Supported

| | |
|---|---|
| Lidarr | **3.1.6.5079** only, official binary or LinuxServer.io image `3.1.6.5079-ls49` (both tested) |
| OS | Linux, including Docker. Other operating systems: the plugin stays inactive and reports an error. |
| Download clients | Any stock Lidarr client you select. Tested: SABnzbd 5.1.3 through Lidarr's SABnzbd client, and Usenet Blackhole. |
| Library storage | Local disk, and kernel-mounted SMB/CIFS (tested read-only with this build) |

## Install

**From Lidarr (recommended):**
1. Go to System > Plugins.
2. Install `https://github.com/GQuX/lidarr-plugin-crescendarr`.
3. Restart Lidarr.
4. Check the log for `CRESCENDARR AUDIT_BUILD_READY version=0.25.0-audit-beta.1+… libraryWrites=impossible`.

**Manually:**
1. Download `Crescendarr-v0.25.0-audit-beta.1.net8.0.zip` and its `.sha256` file.
2. Verify the download (see below).
3. Stop Lidarr.
4. Extract the single DLL into `<AppData>/plugins/GQuX/lidarr-plugin-crescendarr/` (in Docker: `/config/plugins/GQuX/lidarr-plugin-crescendarr/`).
5. Start Lidarr.

## Verify the download (SHA-256)

```sh
sha256sum -c Crescendarr-v0.25.0-audit-beta.1.net8.0.zip.sha256
unzip -l Crescendarr-v0.25.0-audit-beta.1.net8.0.zip   # exactly one entry: Lidarr.Plugin.Crescendarr.dll
```

The expected digest is printed in the release-candidate CI run linked in the release. That run built the asset from the tagged commit and passed the read-only scan. The `.sha256` file must match it.

## Upgrade, roll back, uninstall

- **Upgrade:** System > Plugins shows an update when a newer pre-release exists. Install it, then restart. Settings and `crescendarr-audit/` are kept.
- **Roll back:**
  1. Stop Lidarr.
  2. Replace the DLL in `plugins/GQuX/lidarr-plugin-crescendarr/` with the previous release's DLL (verify its SHA-256).
  3. Start Lidarr.
- **Uninstall:**
  1. Set Mode to Disabled, or delete the Crescendarr entry in Settings > Connect.
  2. Click System > Plugins > Uninstall.
  3. Restart Lidarr.
  4. Optionally delete `<AppData>/crescendarr-audit/`.

## Limitations (read before trusting a preview)

- **Lidarr still runs its own automation, and Crescendarr does not stop it.** With Completed Download Handling on (the default), Lidarr imports what it recognises by itself. In our pre-release test Crescendarr previewed a track as **Keep**, because the existing FLAC was better. Stock Lidarr then imported the album on its own and **deleted that FLAC and the album's lyric files**. Crescendarr neither causes nor prevents this. If a preview says *Keep* and you want to keep that file, handle that download manually.
- **An unresponsive SMB/NAS server makes the preview wait.** The preview never reports unreadable files as missing or new. It resumes when the share answers again.
- **SMB/CIFS libraries.** Lidarr's own rescans can re-import whole albums when file timestamps drift. This is stock Lidarr behaviour.
- **Integrity checks.** Only incoming MP3 files are frame-checked for integrity. Other formats are trusted as complete when the client reports them complete.
- **Previews are not promises.** A preview says what this plugin would decide. It does not promise what a future write-enabled build will do. Write-enabled imports are **not available** and not planned for this pre-release.
- **Version numbering.** Lidarr compares pre-release suffixes as text. Future pre-releases will therefore be numbered so that they sort correctly, such as `audit-beta.2`; there will be no `audit-beta.10`.

## What was tested

The candidate was tested before release with a real SABnzbd, a kernel-mounted SMB library and Lidarr's own plugin installer. Install, update detection, upgrade, rollback and uninstall all went through that installer against a local mock of GitHub's API, inside the LinuxServer.io image.

Before and after each test the run compared:
- library audio and lyric bytes;
- Lidarr's track-file, track, lyric, release, album and artist rows;
- Lidarr settings;
- the download folders.

Every library change was traced to Lidarr's own import history, and none to Crescendarr.
